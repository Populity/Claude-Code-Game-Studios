# Reels Wars: Meme Defense — Техническая стратегия до 1.0

**Статус:** Proposed · **Автор:** Technical Director · **Дата:** 2026-10-05
**Цель владельца:** платный продукт ($3+), 50 000+ загрузок, позже IAP и защита.
**Платформы:** Steam (десктоп-обёртка) → мобильные (iOS/Android).

---

## 1. Честная оценка текущего кода

Кодовая база ~1180 строк: `main.js` 583, `models.js` 232, `world.js` 167, `data.js` 128, `audio.js` 49.

### Что сделано хорошо
- **Данные отделены от логики.** `data.js` хранит все параметры героев, уровней и волн. Баланс можно менять, не трогая код.
- **Нет сборки и зависимостей во время выполнения.** Three.js r170 лежит в `vendor/`, проект на ES-модулях запускается с любого статического сервера.
- **Качественная картинка.** GTAO, bloom, SMAA, PMREM, физические материалы. Для жанра это сильное визуальное преимущество.
- **Есть пул для лучей** (`beamPool`) и ограничение числа частиц (`MAXP`).
- **Есть дымовой тест.** `qa-smoke.mjs` проходит меню → уровни → бой → босс → ульта, сохраняет скриншоты и собирает ошибки консоли. Тест работает через хук `window.__game`.

### Долг прототипа (по убыванию риска)
| # | Проблема | Почему это важно |
|---|---|---|
| D1 | **Монолитный `main.js`.** Рендер, камера, частицы, бой, ввод, HUD, меню и сохранения в одном файле. | Ни одну систему нельзя протестировать или заменить отдельно. Каждая новая фича увеличивает связность. |
| D2 | **Глобальное изменяемое состояние `G`.** Его меняют все функции, а наружу оно открыто через `__game`. | Нет границы «симуляция/представление». Читы делаются из консоли (для single-player это приемлемо, для IAP — нет). |
| D3 | **Логика не тестируется.** Урон, замедление, сплэш, экономика и волны вычисляются внутри кадра вместе с Three.js и DOM. | Нельзя написать юнит-тест без браузера. Ошибки баланса находятся только в плейтесте. |
| D4 | **Подписи из DOM.** HP-бары и всплывающий урон — это `div` в `#labels`, их пересчитывают и раскладывают каждый кадр. | Layout thrash. На мобильных при 40+ врагах это главный кандидат на просадки FPS. |
| D5 | **Аллокации в каждом кадре.** `pos.clone()`, `new Vector3` в частицах и лучах, `new Plane`/`Vector3` при каждом движении мыши, `BufferGeometry` и материал на каждый выстрел (`Line`, `Ring`, огненный шар). | Паузы GC и утечки GPU-памяти, если `dispose` не вызывается. |
| D6 | **Процедурные меши без инстансинга.** Враги и союзники собраны из 10–20 `Mesh` с отдельными материалами. | Растёт число draw calls. Каждый враг — это десятки вызовов. |
| D7 | **Тяжёлые GLB.** `sigma.glb` весит 3.8 МБ, `rizz.glb` — 3.4 МБ, без сжатия. | Время загрузки и VRAM на телефонах. Масштабировать это на 10+ героев нельзя. |
| D8 | **`preserveDrawingBuffer: true`.** Нужен только тесту для скриншотов. | На мобильных GPU это даёт заметную потерю производительности. |
| D9 | **Сохранения в одном ключе `localStorage`.** Нет версии схемы, миграций и контрольной суммы. | Обновление может «сломать» прогресс. В обёртках (Tauri/Capacitor) хранилище WebView иногда очищает ОС. |
| D10 | **Строки вшиты в разметку.** Русский текст захардкожен в `innerHTML` и `data.js`. | Steam-аудитория в основном англоязычная, без локализации 50k не набрать. |
| D11 | **Минимальное аудио** (49 строк). | Звук — половина «сочности» и одно из ожиданий от платной игры. |

**Вывод:** это сильный вертикальный срез с хорошим визуалом, но не основа для продукта. Переписывать с нуля не нужно. Нужен **поэтапный рефакторинг**: разделить симуляцию и представление, затем добавить пайплайн ассетов и сборку.

## 2. Платформа и упаковка

### Варианты
| Критерий | A. Three.js + Web + обёртки | B. Порт на Godot 4.6 | C. Порт на Unity |
|---|---|---|---|
| Время до Steam | **~4–6 недель** (рефакторинг + Tauri) | 3–4 месяца (переписать всё, заново собрать шейдеры и пост-эффекты) | 3–4 месяца + лицензирование |
| Производительность на средних телефонах | Средняя: WebView + WebGL2, нужны жёсткие уровни качества | Хорошая (нативный Vulkan/GLES3) | Хорошая |
| Требования магазинов | Steam: ок. App Store: Capacitor-приложения допускаются, если они не «просто сайт» (офлайн-бандл, нативный IAP) | Без проблем | Без проблем |
| Веб-демо и виральность (itch, CrazyGames, Poki, ссылки из Reels) | **Родная платформа** | Web-экспорт Godot тяжелее и хуже на iOS Safari | WebGL-сборка Unity тяжёлая |
| Риск | Производительность WebView на Android low-end | Полная потеря текущего кода, знания API 4.4+ у ИИ неполные | Стоимость, большой объём |

### Рекомендация: **Вариант A**
1. **Время выхода на рынок важнее всего.** Игра про мемы живёт по циклу трендов, и опоздание на 3 месяца стоит дороже 20% FPS.
2. **Веб — канал маркетинга.** Бесплатное демо в браузере плюс ссылка на Steam — это главная воронка для 50k загрузок. В A она есть бесплатно.
3. **Десктоп: Tauri 2, а не Electron.** Бинарник ~10 МБ против ~150 МБ. Есть Rust-ядро для файлов и Steamworks (через `steamworks-rs`). Риск: на Linux/Steam Deck используется WebKitGTK, где WebGL работает хуже. **Митигация:** заранее прогнать прототип на Deck. Если результат плохой, перейти на Electron (переход дешёвый, код игры тот же).
4. **Мобильные: Capacitor 7**, с обязательной системой уровней качества (раздел 4). Выход на мобильные — во вторую волну, после Steam.
5. **Точка пересмотра:** если на эталонном Android (Snapdragon 6-й серии / Mali-G57) после оптимизаций не держится 30 FPS на уровне Low, оценить порт мобильной версии на Godot. Симуляция, выделенная в чистый JS, станет спецификацией для порта.

## 3. Целевая архитектура 1.0

### 3.1 Модули (ECS-lite: «системы над простыми массивами»)
```
src/
  core/        loop.js (фиксированный шаг 1/60 для симуляции + рендер с интерполяцией), events.js (шина), rng.js (сидируемый)
  sim/         ← чистый JS, НЕТ импорта three/DOM — тестируется в Node
    state.js   createState(levelDef, seed) — вся мутабельная игра
    waves.js, enemies.js, targeting.js, combat.js, economy.js, allies.js, ult.js
  render/      renderer.js (композер + уровни качества), scene.js, camera.js,
               enemyView.js (InstancedMesh), heroView.js (GLB), fx/ (пулы частиц/лучей/колец),
               labels.js (HP-бары как InstancedMesh-спрайты в WebGL, не DOM)
  ui/          HUD/меню на DOM (остаётся DOM — это нормально для меню), i18n-привязки
  platform/    storage.js, steam.js, iap.js, haptics.js — интерфейс + реализации web/tauri/capacitor
  data/        heroes.json, levels.json, waves.json, strings/{ru,en,...}.json
```
**Контракт:** `sim` выдаёт события (`enemyHit`, `enemyKilled`, `heroFired`…). `render` и `audio` на них подписываются. `sim` ничего не знает о том, как это показать. Отладочный хук `__game` остаётся только в dev-сборке.

### 3.2 Ассет-пайплайн
- Исходники `.blend`/`.glb` лежат в `assets/src/`, результат сборки — в `public/assets/` (через скрипт `tools/build-assets`).
- `gltf-transform optimize`: **meshopt**-сжатие геометрии (лучше Draco по скорости декодирования, есть в r170 через `MeshoptDecoder`), квантование, `dedup`, `prune`, `resize` текстур до 1024 (Low — 512).
- Текстуры в **KTX2/Basis** (UASTC для нормалей, ETC1S для остального) через `KTX2Loader`. Это даёт 4–6× экономии VRAM.
- Бюджет на героя: **≤ 600 КБ GLB, ≤ 15k треугольников, 1 материал**. Процедурные враги запекаются в GLB или объединяются через `mergeGeometries` в одну геометрию на тип.

### 3.3 Сборка
- **Vite**: dev-сервер с HMR, `three` из npm вместо `vendor/` (с зафиксированной версией), tree-shaking, хеши в именах файлов, `import.meta.env.DEV` для отладочных хуков.
- Цели сборки: `web` (демо), `tauri`, `capacitor`. Реализация `platform/` выбирается через alias.

### 3.4 Сохранения
- Схема `{ v: 3, profile, progress, settings, purchases }`, цепочка миграций `migrate[v]`.
- Хранилище за интерфейсом: web → `localStorage`/IndexedDB, Tauri → файл в `appDataDir`, Capacitor → `Preferences`/файл. **Steam Cloud** — через файл.
- Атомарная запись (temp + rename), резервная копия, контрольная сумма для обнаружения повреждений.

### 3.5 Настройки и локализация
- Настройки: качество (Auto/Low/Med/High/Ultra), масштаб разрешения, громкость по шинам, язык, тряска камеры, цветовые профили, ограничение FPS.
- i18n: JSON-словари по ключам, `t('hero.sigma.name')`, ICU-плюрализация (`Intl.PluralRules`). Языки 1.0: **EN, RU, ES-LatAm, PT-BR**. Шрифт с кириллицей и латиницей, эмодзи заменить на иконки (на разных ОС эмодзи выглядят по-разному).

### 3.6 Аудио
- Переход на **Howler.js** или собственный граф WebAudio. Шины master/music/sfx/ui, вариации тона и громкости, ограничение одновременных одинаковых SFX (не больше 4), спрайт-атласы, музыка в OGG/AAC со стримингом. Разблокировка AudioContext по первому вводу (обязательно для iOS).

## 4. Бюджет производительности

| Платформа | Цель FPS | Уровень по умолчанию | Draw calls | Треугольники | JS heap | VRAM | Загрузка до меню |
|---|---|---|---|---|---|---|---|
| Steam ПК (GTX 1050 / Iris Xe) | 60 (опц. 120+) | High | ≤ 250 | ≤ 1.5M | ≤ 250 МБ | ≤ 512 МБ | ≤ 3 с |
| Steam Deck | 60 (кап 40 допустим) | Medium | ≤ 200 | ≤ 800k | ≤ 200 МБ | ≤ 384 МБ | ≤ 5 с |
| Mobile средний (SD 6xx, A13+) | 30 стабильно (60 на iOS) | Low/Medium | ≤ 120 | ≤ 300k | ≤ 150 МБ | ≤ 256 МБ | ≤ 6 с |
| Web-демо | 60 / 30 | Auto | как Medium | — | — | — | ≤ 8 МБ первый бандл |

**Уровни качества**
- **Low:** без GTAO и bloom, FXAA вместо SMAA, renderScale 0.75, тени 1024 без мягкости, частиц 30%.
- **Medium:** bloom включён, GTAO в половинном разрешении, тени 2048.
- **High:** всё включено, DPR до 1.5.
- **Ultra:** DPR нативный.
- **Auto:** замер в первые 3 с плюс динамическое разрешение (снижать при frame time > бюджета 2 с подряд).

**Как измерять**
- В dev-сборке оверлей: `renderer.info` (calls, triangles, geometries, textures), frame time p50/p95, `performance.memory`.
- Детерминированный бенчмарк-сценарий (уровень 3, волна 8, x3, фиксированный сид), который выводит JSON. Запускается в CI на SwiftShader только для регрессии draw calls и количества объектов, а не FPS.
- FPS измеряется **вручную на эталонных устройствах** перед каждым релизом: ПК, Deck, один Android среднего класса, iPhone 11. Результаты записываются в `production/qa/perf-[date].md`.
- Контроль утечек: `renderer.info.memory.geometries` не должен расти между волнами.

## 5. Монетизация и безопасность

### Модель
Премиум $3–5 на Steam. На мобильных — бесплатно + разблокировка полной версии (IAP) или премиум. **Не делать** pay-to-win валюту на старте. Косметика (скины героев) и DLC-уровни идут после 1.0.

### Интеграция по магазинам
| Магазин | Покупка игры | IAP / DLC | Технология |
|---|---|---|---|
| Steam | Steam сам | DLC (`BIsDlcInstalled`) или Microtransactions (нужен сервер) | `steamworks-rs` в Tauri-ядре, команды в JS. Достижения и Cloud — там же |
| Google Play | Play | Play Billing v7 | `cordova-plugin-purchase` (CdvPurchase v13) или RevenueCat Capacitor SDK |
| App Store | App Store | StoreKit 2 | то же. **RevenueCat рекомендуется**: одна SDK, серверная валидация чеков из коробки, бесплатно до $2.5k MTR |
| Web | itch.io / Stripe | — | демо без покупок, ссылка на Steam |

### Валидация чеков
- **DLC Steam:** проверяется клиентом через Steamworks, сервер не нужен.
- **Мобильные IAP:** валидация на сервере обязательна для защиты от фейковых чеков (Lucky Patcher и т.п.). Варианты: **RevenueCat** (без своего бэкенда) или свой минимальный сервер (Cloudflare Workers + App Store Server API / Google Play Developer API). На старте рекомендуется RevenueCat.

### Защита сохранений — реалистичный уровень
- Игра однопользовательская, **без таблиц лидеров и онлайн-экономики**. Читы в сохранениях вредят только самому читеру. Тратить время на обфускацию и антитампер **не нужно**.
- Минимум: HMAC-контрольная сумма для обнаружения *повреждений* (а не взлома), версия схемы.
- **Права на покупки не хранить в сохранении.** Источник истины — магазин (Steam DLC API / RevenueCat entitlements), локально только кеш.
- Если появятся лидерборды: валидация на сервере по реплею (детерминированная `sim` + сид + лог ввода). Это ещё одна причина делать симуляцию чистой и детерминированной.
- Гигиена: CSP в обёртках, отключённые devtools в релизной Tauri-сборке, белый список Tauri-команд, без `eval`/`innerHTML` с внешними данными, подпись бинарников (Windows code signing, Apple notarization).

## 6. QA и CI

- **Юнит-тесты логики:** Vitest для `src/sim/*` в Node, без браузера. Покрыть формулы урона, замедления и стана, сплэш, выбор цели, экономику (стоимость, апгрейды, продажа), генерацию волн, условия победы и поражения, миграции сохранений. Цель — ≥ 80% строк `sim/`. Тест на детерминизм: один и тот же сид и лог ввода дают одинаковый хеш состояния.
- **Дымовой тест:** `qa-smoke.mjs` перевести на `@playwright/test`. Порт брать из env, а не 8123. Добавить ассерты: нет ошибок консоли, `G.over === false` после боя, число врагов > 0, `renderer.info.render.calls` ≤ бюджета.
- **GitHub Actions** (`.github/workflows/ci.yml`): `npm ci` → `vitest run` → `vite build` → `npx playwright install chromium` → smoke против `dist/`. Скриншоты загружаются как artifact и копируются в `production/qa/evidence/[date]/`. Без зелёного CI мержа нет.
- **Визуальная регрессия:** `toHaveScreenshot` с допуском ~2% только для меню и HUD (3D-сцену на SwiftShader сравнивать не стоит из-за шума GTAO).
- **Ручная матрица** перед релизом: ПК/Deck/Android/iOS, чек-лист из раздела 4.

| 15 | Capacitor + RevenueCat (unlock full game), прогон на эталонном Android | 6 д | 9, 10 |

**Итого:** ~44 дня, то есть ~9–10 недель для одного разработчика или ~5–6 недель для двух. Steam-релиз возможен после пунктов 1–14.

**Как поймём, что решения верные:** `sim/` покрыт тестами и не импортирует three/DOM; на эталонном Android уровень Low держит 30 FPS при 60 врагах; GLB героя ≤ 600 КБ; CI зелёный на каждом PR; сборка Tauri ≤ 30 МБ.
